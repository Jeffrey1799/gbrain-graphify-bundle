GBrain Knowledge Base

Source Repo: github.com/garrytan/gbrain | Main Contributors: Garry Tan (Creator), Claude, clarajohan, Harshaldorlikar, pkyanam

An AI-managed project knowledge base — solving the problem of "forgetting code once written" and "losing knowledge when people leave".

What is GBrain? In simple words

GBrain = A local search engine + knowledge base that searches your notes.

You dump Markdown notes into it, and you can search them in natural language later. It is not a code generator or a project management tool — it is your team's second brain.

What problem does it solve?
  • When colleagues leave, no one can explain the code logic and architectural decisions clearly.
  • You encountered a bug that was fixed three months ago, but now you have to troubleshoot it from scratch.
  • Every new hire takes weeks to understand the overall picture of the project.
  • Technical documentation is written but never read, and hard to search.
Core Value
BeforeAfter
"Why was this module designed this way?" → Go ask people→ Search the brain, get the answer instantly
"Was this bug fixed before?" → Dig through Git logs→ The brain auto-records, direct match next time
New colleague onboarding → Read docs + ask people→ AI auto-analyzes the project, writes into the brain
Ideas and experiences → Write notes that collect dust→ Talk to AI, auto-saved in the brain
What it can do
  • Search tech notes and architectural decisions
  • Record lessons learned from pitfalls
  • Let AI understand project context
  • Help new employees onboard quickly
What it is NOT
  • Not a code generator
  • Not a project management tool
  • Not CI/CD
  • Not an online service — data is stored locally

GBrain Terminal Commands and Usage

In daily use, you can run commands in the console to manage your knowledge base. Here are the core commonly used commands and their usages:

Key Concept: If you have integrated GBrain with an AI Agent (e.g., Codex or Claude Code), you do not need to learn or manually execute these terminal commands! The AI Agent will call the corresponding commands in the background automatically. You only need to talk to the AI Agent in natural language (e.g., "help me find how we fixed the serial deadlock before" or "record the pitfall I just encountered"), and the AI will handle the command invocations to retrieve or save knowledge (see details in the Work with AI Agent section).

1. Full-text Search (Offline Keyword Search, Most Common)

Search for all documents containing specific words in the GBrain database, no API key required, fully offline and standalone:

gbrain search double_click

2. Conceptual Fuzzy Search (Requires API Key Configuration)

Perform semantic matching using vector models. Even if the search query doesn't appear in the notes, it can match similar meanings:

gbrain query physics red-dot sampling optimization

3. Read a Specific Note Precisely

If you know the unique identifier (Slug) of a note, you can fetch and print its full Markdown content directly:

gbrain get project_overview

4. Write or Update a Specific Note

Save or update Markdown content to the corresponding Slug in the brain via standard input or file redirection:

gbrain put project_overview < overview.md

5. Ingest External Source Files

Import various source files (such as audio/video transcripts, paper PDFs, meeting minutes, etc.) and generate structured notes:

gbrain ingest meeting_transcript.txt --type transcript

6. Sync Local Files and Database

Sync local Markdown file modifications back to the local database index:

gbrain sync

Deadlock Bug Analysis

Symptom
Connect to serial port → Disconnect → Reconnect. The serial port seems to open but no data flows, and the game doesn't respond.

Root Cause (v0.0.56)
The code directly transferred port.readable to the Web Worker:

// Wrong way in v0.0.56
const readable = selectedPort.readable;
worker.postMessage({ type: 'START_SERIAL', readable }, [readable]);

The second argument of postMessage, [readable], transfers the readable stream to the Worker thread, causing the main thread to lose the lock on this stream forever. When port.close() is called, the main thread waits for the readable stream to be unlocked, while the Worker holds the lock → deadlock.

Fix (v0.0.57)
Introduce a TransformStream transit channel so the main thread retains control over the passthrough:

// Correct way in v0.0.57
const passthrough = new TransformStream<Uint8Array, Uint8Array>();
serialPipeClosedRef.current = readable.pipeTo(passthrough.writable).catch(() => {});
worker.postMessage(
  { type: 'START_SERIAL', readable: passthrough.readable },
  [passthrough.readable]
);

Key changes:

  • The main thread pipes readable to passthrough.writable, preserving the Promise of the pipe.
  • Only passthrough.readable is transferred to the Worker.
  • Await serialPipeClosedRef.current before closing to ensure the pipe is completely drained.

Lessons
Never transfer port.readable directly to a Worker. Use TransformStream as an intermediary to let the main thread retain lifecycle control. Wait for the pipe to drain before each close.

Work with AI Agent: Brain-First Mode

Key Concept: From "Manual Search" to "Auto-Collaboration"

GBrain is essentially a powerful set of tools for knowledge base construction and retrieval. If it is only manually run by humans in the command line (such as manually typing gbrain search / gbrain query), it is at best a local personal Wiki tool. Frequently switching and copying/pasting during coding creates a fragmented development experience.

The secret to truly releasing GBrain's power lies in integrating it into an AI Agent (e.g., Codex or Claude Code). By letting the AI handle execution, matching, reading, and writing in the background, GBrain is seamlessly integrated into your daily AI-assisted development workflow. At this point, GBrain becomes the AI's "external hard drive" and "experience cache" — AI searches for you, AI consolidates for you, and human-computer collaboration efficiency multiplies exponentially.

Data Safety: By default, GBrain stores all data on the local hard drive, and basic features do not require internet access. Network requests are only made when semantic search is enabled (requires OpenAI Embedding configuration) or when using a remote database (Supabase).

Once connected, this is the most valuable way GBrain works — before answering any questions, the AI Agent will search GBrain first, giving answers with the project context in hand:

Core Collaborative Relationship: Four Roles in AI Agent Workflow

In a knowledge-base-driven AI collaborative development process, technical concepts can easily get confused. Here is their clear division of labor and positioning in the workflow:

Tech Component Role (Metaphor) Core Function / Responsibility Specific Action in Practice
AI Agent
(e.g., Codex / Claude Code)		 Executive Officer (Agent Body & Toolset) Interacts with the user, reads your instructions, breaks them into tasks, and calls terminal tools (e.g., reading files, running tests, database I/O) to work automatically. When you say "check the principle of red dot double click", the AI Agent calls GBrain to query and consolidates the notes.
GBrain
(Local Engine & DB)		 Local Archive Room (Knowledge Base) The local physical archive storing all tech notes, design docs, and architectural understandings. Provides local high-concurrency reading, writing, filtering, and DB storage. Responsible for safely and privately persisting project Markdown notes (e.g., .gbrain-md/) to the local GBrain database in real-time.
Vector Model
(e.g., ZeroEntropy / OpenAI embedding)		 Translator (Semantic Feature Extractor) Translates natural language documents and code in GBrain into "semantic fingerprints" (Embedding vectors) in a high-dimensional space, enabling concept-level similarity matching. When the AI Agent wants to search across languages/concepts (e.g., matching Chinese "双击" with English "double click"), the vector model enables fuzzy semantic search.
LLM Large Model
(e.g., Claude 3.5 Sonnet / Gemini Pro)		 Decision Brain (Reasoning Center) Provides logical analysis, code understanding, summarization, and text generation. Responsible for reasoning and consolidating retrieved information. When GBrain retrieves relevant notes and code snippets, the LLM logically pieces them together, distills pitfalls, and generates the final high-value answer.
Collaboration Workflow in One Sentence:
You instruct the AI Agent to work ➡️ The AI Agent automatically requests documents from the GBrain Archive ➡️ The Vector Model helps GBrain perform fuzzy semantic matching to pull the most relevant notes ➡️ The LLM Large Model deeply reasons and synthesizes these notes to present the best distilled solution to you.

FAQs

How do I resolve Git SSL connection reset errors during installation on Windows?

Symptom: git clone reports schannel: SSL connection reset or Failed to receive handshake, SSL/TLS connection failed.

Reason: Windows' Schannel SSL backend fails to handshake with GitHub through local proxies (like 127.0.0.1:7897).

Solution: Bypass proxy temporarily during clone: git -c http.proxy="" clone https://github.com/garrytan/gbrain.git ~/gbrain --depth 1.

What should I do if Bun global install (bun install -g) crashes on Windows?

Symptom: bun install -g github:garrytan/gbrain crashes during tarball extraction or gbrain doctor reports schema_version as 0.

Reason: Bun's support for global postinstall scripts on Windows is unstable, and schema migrations are not auto-executed.

Solution: Use a deterministic installation path — clone the source code and build locally: git clone ... && cd ~/gbrain && bun install && bun link.

Is my GBrain data safe? Will it leak to the internet?

Basic features run completely locally. Currently using PGLite (embedded local Postgres). All data is stored in ~/.gbrain/brain.pglite with no network requests.

  • Network requests are only made during git clone and bun install (one-time).
  • When ZeroEntropy API Key is configured, data outbounds (text fragments only) occur during embedding model calls.
  • Without configuring a remote database (Supabase), data will not be uploaded to the cloud.
Do I need an API key? Which provider should I use?

Basic features (keyword search gbrain search, saving notes) do not require an API key.

To enable semantic search (gbrain query), GBrain uses ZeroEntropy's zembed-1 embedding model (1280-dimension) and zerank-2 reranking model by default. You need to configure the ZEROENTROPY_API_KEY environment variable.

You can also switch to OpenAI's embedding models, but currently, the ZeroEntropy solution is tested and works properly.

What is "Semantic Search"? What is its relationship with search.mode?

Semantic Search (API Key) determines whether fuzzy semantic matching is possible — searching for "trackpad" can find "TrackPoint" even if the keywords don't match exactly.

search.mode determines how much context and token budget each search consumes, which is independent of whether you have an API key:

  • conservative: 4K tokens, 10 fragments, saves the most tokens.
  • balanced (recommended): 12K tokens, 25 fragments, Sonnet-level cost-performance.
  • tokenmax: no budget limit, 50 fragments, most comprehensive.

The two concepts are orthogonal. You can change search.mode without an API key, and select conservative even with an API key.

Since notes are stored in the database, how do I view them in a text editor?

The GBrain database (PGLite) is binary and cannot be opened directly in an editor. However, our prompt requires Write-Through — creating a brain page will also write a .md file to ~/brain/projects/<project_name>/ and commit it to Git.

So you can:

  • Search knowledge: Say "search for project XXX" to the AI ➡️ AI queries the database.
  • View raw notes: Directly open ~/brain/projects/<project_name>/*.md ➡️ Text editor.

If a note exists only in the database but not in the repo, run gbrain sync --push to sync it back to the repo.

How are multiple projects isolated?

Currently using a Single-Brain Topology (Topology 1) — all projects share the same PGLite database, isolated by namespace:

  • Project A knowledge ➡️ projects/project-a/*
  • Project B knowledge ➡️ projects/project-b/*

If you want completely independent database instances, use the Split-Engine Topology (Topology 3): create independent PGLite instances for each project using the GBRAIN_HOME environment variable.

Can data in the brain be exported?

Yes. There are two ways:

  • Via repository: ~/brain/ itself is a Git repository, and all .md files can be copied, committed, and shared directly.
  • Via commands: gbrain get <slug> prints the full Markdown, which can be redirected to a file.
  • Via MCP: Use list_pages to list all pages + get_page to read them one by one.
What should I do if gbrain doctor errors on Windows?

Symptom: gbrain doctor --json output is empty, or reports a PGLite lock timeout.

Reason: Bun's handling of large JSON outputs on Windows is unstable, and PGLite is occupied during MCP connection.

Solution:

  • Fetch the full health report by calling the run_doctor tool via MCP.
  • Or disconnect MCP and run gbrain doctor separately in a terminal.
How do I upgrade GBrain?

For Git clone installations, run: 

cd ~/gbrain && git pull origin master && bun install
gbrain apply-migrations --yes
gbrain post-upgrade

Then run gbrain doctor (or run_doctor via MCP) to verify the health status.

If installed via bun install -g, the upgrade command is gbrain upgrade.

How do I reuse the project brain on other projects?

You only need to copy the prompt. Send the optimized prompt from the "Project Brain" section to the AI Agent in the new project. The AI will automatically:

  1. Scan the code structure and Git history of the new project.
  2. Create projects/<new_project_name>/* pages in GBrain.
  3. Sync .md files to ~/brain/projects/<new_project_name>/.
  4. Verify retrieval effects.

No need to reinstall GBrain or reconfigure MCP.

Graphify Project Knowledge Graph

Official Repo: github.com/Graphify-Labs/graphify | Official PyPI Package: graphifyy (Command remains graphify)

Let AI connect code, documents, PDFs, images, and architectural specifications into a searchable, traceable project map.

What is Graphify? In simple words

Graphify = Turns code and document relationships in the current project into a persistent knowledge graph.

It parses functions, classes, calls, imports, inheritance, and dependency relationships through AST, and then connects concepts, design rationale, and implementation code in non-code assets like Markdown, PDFs, and images. Once constructed, the AI doesn't need to traverse the entire repository from scratch every time; it can query the graph first and then locate the source files by evidence.

What will you get after building?
ArtifactPurpose
graphify-out/graph.htmlAn interactive graph in the browser to search nodes, view communities, and connections.
graphify-out/GRAPH_REPORT.mdAn architectural summary for humans and Agents: core nodes, communities, unexpected connections, and suggested questions.
graphify-out/graph.jsonComplete, persistent graph data for CLI, Skills, MCP, and other GraphRAG tools to query.
graphify-out/cache/Incremental build cache; subsequent --update only processes new or changed files.
Especially suitable for
  • Quickly understanding module boundaries and core data flows in a strange codebase.
  • Querying the relationships between a class, function, or configuration and other components.
  • Connecting protocol specifications, architecture documents, and screenshots with implementation code.
  • Evaluating which communities and dependencies a PR, modification, or refactoring might affect.
Do not misunderstand as
  • Not a long-term memory database that automatically records all conversations.
  • Not a vector database, nor a pure keyword index.
  • Will not naturally understand all pitfall lessons from Git history.
  • Cannot replace source code, tests, Git evidence, and manual reviews.

How to distinguish "Facts" and "Inferences" in the graph?

Graphify tags relationships with evidence levels. You should prioritize relationships extracted directly from source materials, and review inferred relationships against the source code:

TagMeaningUsage Advice
EXTRACTEDThe relationship exists directly in the source code, documents, or explicit references.Highly credible clues, but you should still check source files before making important changes.
INFERREDRelationships deduced by Graphify based on naming, parsing, and context.Suitable for discovering hidden connections, not to be taken as direct proof of developer intent.
AMBIGUOUSMultiple possible matches exist and cannot be uniquely determined.Must be resolved manually by combining file paths, symbol definitions, call sites, and tests.

Graphify & GBrain: Complementary, Not Substitutes

Core Difference: GBrain is like a "long-term knowledge archive", while Graphify is like a "current project structure map". The former excels in saving experience and notes, while the latter excels in showing relationships between code, documents, and components.
DimensionGraphifyGBrain
Core Data StructureKnowledge graph of nodes, edges, and communitiesSearchable and writable knowledge pages and notes
Primary SourcesWorkspace code, documents, images, PDFs, configurationsLong-term experiences, decisions, meetings, and pages distilled by humans or Agents
Strongest CapabilityModule relationships, call paths, dependencies, architectural navigation, impact areaExperience reuse, historical lessons, decision backgrounds, long-term cross-project memory
Update MethodRebuild graph or run --update for incremental refreshContinuously add or update knowledge pages
Query Methodquery, path, explain, and MCP graph toolsKeyword, semantic search, page reading and writing
With Graphify Only

You get a high-quality project structure map, suitable for current codebase understanding, relationship query, and impact analysis; but historical bug lessons will not appear out of nowhere unless they are already written in code comments, docs, commit messages, or Markdown distilled by Agents.

With Graphify + GBrain

Graphify provides "what the project looks like now", and GBrain saves "why it was done this way and what pitfalls were encountered in the past". The Agent can query long-term experiences first, and then use the graph map to locate current implementations and impact paths.

Project Graph: Graphing the Codebase

Building the project graph allows Graphify to analyze codebase dependencies, structure, and semantic files. Refer to Step 2 of the Quickstart section to invoke the graph generation prompt.

Core CLI Commands for Construction

1. Parse and extract workspace to build a graph (supports update)

Standard local extraction mode. Extracts AST structure locally, handles non-code assets according to constraints, and outputs the graph files to graphify-out/:

graphify extract .

2. Incremental update (recommended after code changes)

Only scans files changed since the last extraction, updating node/edge attributes and community boundaries in graph.json. Much faster than a full rebuild:

graphify extract . --update

3. Force full rebuild

Clears cache and rebuilds the entire graph from scratch. Use this when schema structures change or graph files are corrupted:

graphify extract . --force

FAQs

Should I install graphify or graphifyy?

The official PyPI package name is graphifyy (with double y). Once installed, the CLI command is still graphify, and the MCP command is graphify-mcp. Do not install other PyPI packages with similar names.

Does codebase analysis require an API Key?

Code AST extraction runs completely locally and does not require an API Key. Semantic extraction of documents, PDFs, and images uses the model of the current AI Agent, or the model backend configured in headless CLI mode. Confirm data egress rules when dealing with confidential materials.

Why can't I find the graphify command after installation?

The executable directory of uv tool might not be added to your current shell's PATH. Run uv tool update-shell and reopen the terminal. In the current session, you can also verify using the absolute executable path found by the Agent.

Why does /graphify . error in Windows PowerShell?

/graphify is a Skill command within the AI Agent, not a PowerShell command. In PowerShell, run the CLI directly using graphify .. In Codex, use $graphify ..

What is the difference between MCP and the Graphify Skill?

The Skill is responsible for reading the workspace, scheduling extraction, and generating/updating the graph. The MCP loads an existing graph.json to provide structured query tools for the Agent. Typically, you install the Skill and generate the graph first, and then configure the MCP. MCP is not a prerequisite for graph generation.

What if jieba installation fails for Chinese word segmentation?

When installing graphifyy[mcp,chinese]==0.9.30 on Windows via uv tool install, jieba might fail because the uv sandbox cannot delete cache files or due to mirror hash mismatches.

Solution: Download and build the wheel for jieba from PyPI using pip first, and then inject it via uv tool install --with <wheel_path>. Steps:

pip install jieba --index-url https://pypi.org/simple --trusted-host pypi.org --trusted-host files.pythonhosted.org
# Find the wheel path in pip cache
ls /c/Users/xxx/AppData/Local/pip/cache/wheels/*/*/*/jieba-*.whl
# Install with uv tool install --with specifying local wheel
uv tool install --force "graphifyy[mcp,chinese]==0.9.30" --with /path/to/jieba-0.42.1-py3-none-any.whl

You can also temporarily omit the chinese extra and add it later using the method above.

Path parameters error in Windows Git Bash?

When passing absolute paths (like /c/Users/xxx/project) to commands like graphify extract in Git Bash, the path might be incorrectly joined as C:\c\Users\....

Solution: Switch to the target directory and use . as the path parameter directly, or use complete Windows path format (containing double backslashes) wrapped in quotes.

The Agent still cannot find graphify-mcp after MCP configuration?

After modifying mcp.json to add the Graphify MCP server, the current AI Agent session will not reload the new MCP server automatically. You must restart the Agent session to make the mcp__graphify__* tools visible in the tool list. This is a platform limitation, not a configuration error.

Running the install command fails due to Windows sandbox issues?

Re-running a Graphify platform integration command on Windows might fail with SAFE_DELETE_FAIL_CLOSED because the sandbox cannot delete the old skill references directory.

If the skill files already exist and work properly, this error can be safely ignored. For a clean reinstall, confirm and remove the Graphify skill directory for the current platform, then rerun its official install command.

Does it support PPTX?

The current official file support matrix lists DOCX, XLSX, PDF, images, and Google Slides shortcuts, but not local PPTX extraction directly. It is recommended to let the Agent convert PPTX to PDF or structured Markdown first, and then ingest it via Graphify.

What if Chinese query results are not satisfying?

Install graphifyy[mcp,chinese]==0.9.30 to enable the MCP server and jieba Chinese word segmentation; meanwhile, try to include actual class names, function names, module names, or protocol names in your queries. Always verify graph queries against the source files.

How do I update Graphify?

The safest way is to run the "Installation Prompt" in this guide again, letting the Agent use uv tool install --force to update the same set of extras from official docs. Re-register the Skill after upgrading, and run graphify hook install again to refresh the interpreter path embedded in the Hook.

How do I uninstall?

graphify uninstall removes platform integrations; adding --purge will also delete graphify-out/. Ensure the graph is backed up or committed before executing purge.

What if the graph becomes outdated or queries are inaccurate?

Run --update first, and then repeat your query/path. Consider a full rebuild only if node IDs or schemas are incompatible with newer versions, graph files are corrupted, or a large number of file rules change. Never assume codebase queries are correct just because the command ran successfully.
